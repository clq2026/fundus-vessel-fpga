# 02 算法原理

## 2.1 最终算法流程

```
彩色眼底图
  → [PS] 取绿通道
  → [PS] CLAHE 对比度增强（clip = 2.0，8×8 网格）
  → [PL] 中值滤波 3×3（边界复制）
  → [PL] 黑帽形态学 11×11 矩形核（膨胀 → 腐蚀 → 饱和减，输出原始差值）
  → [PS] MINMAX 归一化到 0–255
  → [PS] Otsu 自适应阈值
  → [PS] 删除面积 < 30 像素的小连通域
  → [PS] 与 FOV 有效视野掩膜相与
  → 血管二值掩膜 → 原图彩色叠加
```

参考实现见 `src/pipeline.py`（`process()` 函数），每一步都有独立开关与中间结果输出。

## 2.2 各步骤的原理

**绿通道**：眼底彩照中，血管与背景的对比度在绿色通道上最大；红通道几乎看不出血管，蓝通道动态范围小。

**CLAHE**：把图像切成 8×8 分块分别做直方图均衡，并限制放大倍数，抑制噪声过增强。放在形态学之前。

**中值滤波 3×3**：每像素取 3×3 邻域 9 个值的中位数。相比均值滤波，中值滤波去噪的同时不模糊血管边缘。

**黑帽 11×11**：血管是"比周围暗的细长结构"。

- 膨胀 = 窗口内取最大；腐蚀 = 窗口内取最小；闭运算 = 先膨胀再腐蚀
- 闭运算会把暗的细线（血管）用亮背景"填平"
- 黑帽 = 闭运算结果 − 原图，被填平的部分重新显现，即血管响应

结构元素取 11×11 矩形核，尺寸需大于血管宽度（血管约 5–10 像素）。

**MINMAX 归一化**：黑帽原始响应动态范围很小（实测约 0–100），直接卡阈值筛不出东西，先线性拉伸到 0–255。

**Otsu 阈值**：按直方图自动选取使类间方差最大的阈值，免去人工调参。它需要整帧统计，因此留在 PS 端。

**删小连通域**：阈值化后残留的孤立噪点面积很小，删除面积 < 30 像素的连通域；血管是细长连续结构，不受影响。

**FOV 掩膜**：眼底照只有中央圆形区域是有效视野，边缘黑色区域易产生误检，用掩膜将其清零。

## 2.3 三版迭代

| 版本 | 相对上一版的改动 |
|---|---|
| V1 | 基础流程：绿通道 → 中值 → 黑帽 → 固定阈值 → 叠加 |
| V2 | 增加 FOV 掩膜、CLAHE、Otsu 阈值、小连通域过滤 |
| V3 | 增加四方向线检测（0°/45°/90°/135°）并与黑帽响应加权融合 |

指标口径：只在 FOV 内统计；宏平均 = 每张图先算再平均。

**共同子集对照（各 10 张，同口径可横比）**

| 数据集_版本 | Dice（宏） | Precision | Recall |
|---|---|---|---|
| STARE_V1 | 0.5331 | 0.8113 | 0.4236 |
| STARE_V2 | 0.7052 | 0.6968 | 0.7274 |
| STARE_V3 | 0.7129 | 0.7105 | 0.7259 |
| DRIVE_V1 | 0.4397 | 0.9508 | 0.2985 |
| DRIVE_V2 | 0.6560 | 0.8677 | 0.5559 |
| DRIVE_V3 | 0.6547 | 0.8812 | 0.5448 |

> V1 与 V2/V3 之间混了两个变量：除算法改动外，V1 没有启用 FOV 掩膜（指标在全图上统计）。
> 所以"V2 比 V1 好多少"是算法与 FOV 共同作用的结果。

**全量 20 张**

| 数据集_版本 | Dice（宏） |
|---|---|
| STARE_V2 | 0.7228 |
| STARE_V3 | 0.7278 |
| DRIVE_V2 | 0.6796 |
| DRIVE_V3 | 0.6784 |

**V3 为什么没有采用**：四方向线检测在 STARE 上 Dice 只提升 0.0077，在 DRIVE 上反而下降 0.0013，
却要多付出四方向卷积与加权融合的复杂度和硬件资源。收益不足以支撑成本，最终采用 V2 作为硬件实现版本。

## 2.4 为什么只把中值与黑帽放进硬件

| 理由 | 说明 |
|---|---|
| 计算量占比最大 | 11×11 窗口形态学相当于每像素 121 次比较，是整条流水线最重的部分 |
| 纯局部窗口运算 | 只需邻域像素，可用行缓存流式实现，不需要整帧缓存 |
| 数据位宽友好 | 输入输出都是 8 bit，与 AXI-Stream 直连，无需位宽转换 |
| 切分干净 | 需要整帧统计的 Otsu 留在软件端，硬件不必做多遍扫描 |

## 2.5 精度水平

数据切分纪律：每个数据集前 10 张作为开发集用于调参，后 10 张作为评价集，调参期间不查看。

| 口径 | STARE | DRIVE |
|---|---|---|
| 开发集（参与调参，10 张） | 0.7052 | 0.6560 |
| **评价集（未参与调参，10 张）** | **0.7404** | **0.7031** |
| 全量 20 张 | 0.7228 | 0.6796 |

评价集反而高于开发集（STARE +0.0352、DRIVE +0.0471），说明参数没有过拟合开发集。

**与人类专家的一致性**：本项目用 `python工具/human_baseline.py` 在本地实测了 STARE 两位标注专家
（`ah` 与 `vk`）之间的相互一致性，Dice 为 **0.7401**；本项目算法在同一批评价集上的 Dice 为 **0.7404**。
两者基本持平，即算法与专家的一致程度已接近专家之间的一致程度。

**为什么用 Dice 而不是 Accuracy**：血管像素只占视野 8% 左右（本项目实测 DRIVE 8.63%、STARE 7.60%），
把所有像素都判成背景就能拿到 DRIVE Accuracy 0.8727，但 Dice 为 0。
本项目 V2 在 DRIVE 上的 Accuracy 为 0.9525，人类专家为 0.9472；但对外汇报一律使用 Dice。

## 2.6 真实拍摄照片的处理

标准数据集之外的实拍照片（如打印的眼底图翻拍）不能直接用 Otsu 自动生成 FOV：
白底场景下自动 FOV 会把整幅图判为有效区域，掩膜失效。`python工具/fundus_autoloc.py` 改用
**R−B 色度分割**定位眼底圆（眼底呈暖红色，R−B 为正；白色泡沫球与木桌面接近 0 或为负），
取最大连通域后先求凸包再填充，半径用最小外接圆估计，再用该圆生成 FOV 掩膜。

实测（打印件翻拍）：Otsu 自动 FOV 下 Dice 为 0.0000，改用圆形 FOV 后为 0.5907。

拍摄要求是正对眼底：斜 20° 时 Dice 降到 0.3233，斜 30° 降到 0.2118。
实拍图与其真值之间存在 2–3 像素、约 2° 的几何偏差，而血管只有 5–10 像素宽，
逐像素 Dice 会因此明显下降，所以实拍场景报告的是"允许配准后的 Dice 上限" 0.6139，
而不是未配准的原始值 0.5150。
