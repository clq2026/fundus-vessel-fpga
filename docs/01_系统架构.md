# 01 系统架构

## 1.1 平台

| 项 | 值 |
|---|---|
| 开发板 | PYNQ-Z2 |
| 器件 | `xc7z020clg400-1`（Zynq-7020） |
| 工具链 | Vitis HLS 2022.2 + Vivado 2022.2（Ubuntu 22.04） |
| PS | ARM Cortex-A9 @ 667 MHz，运行 PYNQ v2.7（板载 OpenCV 4.5.4、numpy） |
| PL 时钟 | 100 MHz（`FCLK_CLK0` = 10.000 ns，单时钟域） |

## 1.2 整体数据流

```
DDR3 ──AXI DMA MM2S──> vessel_top（PL） ──AXI DMA S2MM──> DDR3
                        （中值 3x3 + 黑帽 11x11）
        ↑ M_AXI_GP0（AXI4-Lite 配置）        ↑ S_AXI_HP0（64-bit 高速口）
                        PS（ARM / Python）
```

一帧 605 × 700 × 8 bit = 423,500 字节。PS 端把整帧作为连续字节流交给 DMA，
PL 端以像素流方式逐拍处理，处理结果再经 DMA 写回 DDR，由 PS 继续做归一化、阈值与后处理。

## 1.3 Block Design 组成

| 实例 | IP | 作用 |
|---|---|---|
| `processing_system7_0` | Zynq PS7 | 提供 FCLK_CLK0 100 MHz、M_AXI_GP0 控制口、S_AXI_HP0 高速口（64 bit） |
| `axi_dma_0` | AXI DMA 7.1 | 两通道数据搬运，Simple 模式（无 Scatter-Gather） |
| `vessel_top_0` | 本项目 HLS IP | 中值 + 黑帽，AXI4-Stream 输入/输出 + AXI4-Lite 控制 |
| `ps7_0_axi_periph` | AXI Interconnect | 控制通路，1 主 → 2 从（DMA、IP） |
| `axi_hp_ic` | AXI Interconnect | 数据通路，2 主（MM2S、S2MM）→ 1 从（HP0） |
| `proc_sys_reset_0` | Processor System Reset | 产生 PL 侧 `peripheral_aresetn` |
| `const_zero_0` / `const_one_0` | XL Constant | 固定复位辅助脚电平，避免误触发复位 |

## 1.4 地址与关键配置

| 项 | 值 |
|---|---|
| 血管 IP 控制口 | `0x40000000` |
| AXI DMA 控制口 | `0x41E00000` |
| HP0 数据宽度 | 64 bit |
| DMA AXI 侧 / Stream 侧宽度 | 64 bit / 8 bit |
| DMA burst 长度 | 256 |
| DMA 单次传输长度位宽 | **26 位** |

DMA 长度位宽这一项单独说明：AXI DMA 默认 `c_sg_length_width` 为 14 位，
单次最多 16383 字节，一帧 423,500 字节会被静默截断（实测截成 13900 字节），
MM2S 提前发出 TLAST 导致 IP 挂死。`build_bd.tcl` 中已强制写为 26，
`verify_bd.tcl` 里加了一条硬检查（V-08b），长度上限不足一帧时直接报错中断。

## 1.5 软硬件分工

| 由 PS（ARM / Python）完成 | 由 PL（FPGA）完成 |
|---|---|
| 图像读取、绿通道提取 | 中值滤波 3×3 |
| CLAHE 对比度增强 | 黑帽形态学 11×11（膨胀 → 腐蚀 → 饱和减） |
| MINMAX 归一化、Otsu 阈值 | |
| 删小连通域（< 30 像素）、FOV 掩膜 | |
| 指标统计、交互界面、计时 | |

划分依据见 `docs/02_算法原理.md` 第 2.4 节：中值与黑帽占整条流水线绝大部分计算量，
且二者都是纯局部窗口运算，适合流式实现；Otsu 需要整帧直方图统计，留在软件端避免硬件多遍扫描。

## 1.6 DMA 传输约定

启动顺序（顺序错误会导致传输不触发或状态机卡死）：

1. MM2S 与 S2MM 两通道 `RS = 1`
2. IP `ap_start = 1`
3. 写源地址 SA、目的地址 DA
4. **写 LENGTH —— 到这一步传输才真正开始**

完成判据：读状态寄存器 **bit1 `Idle`**（`SR & 0x02`），不用 bit9 `IOC_Irq`。

另外两点：
- 重载 bitstream 后必须重建 MMIO 与 Buffer；同名 bit 再次加载会被 PYNQ 跳过，不等于复位。
- 若一次传输被中途中止，HLS IP 内部状态会被污染（后续运行耗时正常但像素出错），
  只有重新加载 bitstream 能清除。因此压测的判据是逐像素比对，不是"没有抛异常"。

## 1.7 复现方式

```bash
# 1. 构建 Block Design（Vivado 2022.2）
vivado -mode batch -source vivado_s10/build_bd.tcl
vivado -mode batch -source vivado_s10/verify_bd.tcl   # 硬检查：地址、DMA 位宽、复位电平

# 2. 综合与实现
vivado -mode batch -source vivado_s10/build_synth.tcl
vivado -mode batch -source vivado_s10/build_impl.tcl

# 3. 上板
python3 python工具/demo_s11_board.py
```
