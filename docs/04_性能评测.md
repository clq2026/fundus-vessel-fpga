# 04 性能评测

本文件是全部性能指标的唯一数字来源，汇报与演示引用时以本文件为准。
数据由 `python工具/demo_s11_board.py` 在 PYNQ-Z2 上实测得到。

板上运行的 bitstream 为 v3 最终版，MD5 `ae90e5bd602760edd23ecfde04ffcd08`。

## 4.1 测试条件

加速比脱离条件就没有意义，下面这组参数必须与数字一起给出。

| 项 | 值 |
|---|---|
| 开发板 | PYNQ-Z2（`XC7Z020-1CLG400`） |
| PL 时钟 | 100 MHz（`FCLK_CLK0` = 10.000 ns，单时钟域） |
| PS 时钟 | ARM Cortex-A9 @ 667 MHz |
| 图像 | STARE `im0082` 的 CLAHE 输出，605 × 700，8 bit 灰度（423,500 字节） |
| 对比基线 | 板载 OpenCV 4.5.4（NEON 优化，单线程） |
| 数据通路 | `pynq.allocate` 物理连续缓冲 + AXI DMA Simple 模式 |
| 计时纪律 | 软件与硬件均先预热 1 次，再取多次**中位数**（首测含冷启动开销） |
| 完成判据 | DMA 状态寄存器 bit1 `Idle` 置位 |

## 4.2 三个口径速览

| # | 指标 | 纯 ARM 软件 | 混合硬件 | 加速比 |
|---|---|---|---|---|
| ① | 核心算子（中值 + 黑帽） | 168.79 ms | **4.458 ms** | **37.9×** |
| ② | 端到端 · 不含 FOV 生成 | 281.6 ms | 123.0 ms | **2.29×** |
| ③ | 端到端 · 含 FOV 生成 | 386.0 ms | 227.3 ms | **1.70×** |
| ④ | FOV 掩膜生成（单项） | 1227.9 ms（优化前） | 104.3 ms | **10.9×** |

三个口径一起给：只看核心算子会显得虚高，把前后处理算进去才是真实系统性能。
输出与软件参考在 423,500 像素上**逐像素完全一致**（不一致像素 0，最大差值 0）。

本表是 Demo 最终一轮的实测值；另一轮独立基准为 168.35 / 4.476 ms = 37.6×，
四次独立测量的互差见第 4.10 节（均在 2% 以内）。

## 4.3 核心算子的两种测法

同一个 IP，只差测法，汇报时必须分清：

| 测法 | 数值 | 含义 |
|---|---|---|
| **B · 吞吐口径** | **4.458 – 4.476 ms**（≈ 223 fps） | 预置数据，只计时"写 LENGTH → DMA Idle"这一段，即 IP 搬运 + 计算的硬件时间 → **37.6 – 37.9×** |
| **A · 延迟口径** | **9.4 – 9.7 ms**（≈ 105 fps） | 完整单帧往返，含 PS 侧 `copyto` / `flush` / 取回数组 → 主机侧真实延迟 |

两者相差约 5 ms，全部来自 ARM 侧内存操作，与 IP 本身无关。
**报算法加速比用 B（37.6×），讲系统实时性用 A（105 fps），不要混用。**

## 4.4 端到端逐段耗时

整条流水线：绿通道 → CLAHE → 核心 → MINMAX 归一化 → Otsu → 删小块 → FOV 清零（可选 FOV 生成）。

| 步骤 | 纯软件 (ms) | 混合硬件 (ms) | 段加速比 |
|---|---:|---:|---:|
| 绿通道提取 | 0.04 | 0.04 | 1.0× |
| CLAHE 增强 | 34.20 | 33.32 | 1.0× |
| **核心（中值 + 黑帽）** | **168.40** | **9.46** | **17.8×** |
| 归一化 MINMAX | 27.50 | 27.74 | 1.0× |
| Otsu 阈值 | 5.27 | 5.94 | 1.0× |
| 删小块（< 30） | 46.24 | 46.49 | 1.0× |
| **合计（不含 FOV 生成）** | **281.6** | **123.0** | **2.29×** |
| **合计（含 FOV 生成）** | **386.0** | **227.3** | **1.70×** |

除核心段外，其余步骤仍在 ARM 上运行，因此端到端加速比被 Amdahl 定律压低。
这也明确了下一步的优化方向：把归一化、删小块等步骤继续硬件化。

## 4.5 FOV 生成的优化

原实现沿用了论文"迭代 50 次"的写法，但把论文的**膨胀**换成了**闭运算**，
而闭运算是幂等的（`φ(φ(X)) ≡ φ(X)`），第 2 次起结果完全不变，后 49 次纯属浪费。

| 阶段 | 耗时 |
|---|---:|
| 优化前（闭运算 × 50） | 1227.9 ms |
| 优化后（闭运算 × 1） | 113.1 ms |
| **加速比** | **≈ 10.9×** |

正确性：在全部 20 张 STARE 图上逐像素对照，1 次与 50 次结果**差异 0 像素**，
属于纯实现优化，Dice / Accuracy / Recall 均无需重算（脚本 `python工具/verify_fov_fast.py`）。

对端到端的影响：

| 口径 | 优化前 | 优化后 |
|---|---:|---:|
| 端到端加速比 | 1.12× | 1.66× |
| FOV 在纯软件总时长中的占比 | 81% | 28% |

## 4.6 稳定性与压力测试

**连续 50 帧**（每帧与软件真值比对）：50/50 全部一致，
单帧延迟 min 9.293 / median **9.420** / mean 9.460 / std 0.278 ms，等效 106.2 fps。

**三轮阶梯 AXI 压测，共 2400 帧全部通过**：

| 轮次 | 规模 | 结果 |
|---|---|---|
| 单图连跑 | `im0002` × 200 帧 | median 9.345 ms，std 0.325，漂移 −1.0%，0 帧不一致 |
| 双图交替 | `im0082` ↔ `im0002` × 200 帧 | 各自 0 帧不一致，**串帧计数 0**，两图中位 9.382 / 9.374（差 0.08%） |
| 长时压测 | `im0002` × **2000 帧** | 2000/2000 逐帧对标软件真值全过，median 9.426 ms，std 0.454，漂移 −1.6% |

故障率 < 1/2000 = 0.05%。三轮覆盖了单图、多图交替、长时三种负载，
验证 AXI 握手、真实反压与 TLAST 帧边界在连续数据流下不崩、不劣化、不串帧、零数据错误。

## 4.7 困难图回归

`im0002` 是 20 张 STARE 图中 Dice 最低的一张（0.5564），用它做回归最能说明问题。

| 指标 | `im0082`（基准图） | `im0002`（最难图） |
|---|---:|---:|
| 核心 · 纯软件 | 167.53 ms | 169.34 ms |
| 核心 · 硬件 | 9.65 ms | **9.57 ms** |
| 端到端加速比 | 2.24× | 2.22× |
| 不一致像素 | 0 / 423,500 | **0 / 423,500** |

两条结论：

1. 最难图依然逐像素 0 差异，硬件实现的正确性与图像难度无关。
2. 硬件核心延迟几乎不随图像内容变化（9.65 → 9.57 ms，−0.8%），
   提供的是确定性、可预测的延迟，这正是实时系统需要的性质。

## 4.8 资源占用

Vivado 实现报告（v3 最终版）：

| 资源 | 实现值 | 器件总量 | 占比 |
|---|---:|---:|---:|
| Slice LUTs | 7497 | 53200 | **14.09%** |
| Slice Registers | 10269 | 106400 | **9.65%** |
| Block RAM Tile | 25 | 140 | **17.86%** |
| DSP | 0 | 220 | **0%** |

DSP 用量为 0：形态学只做比较与取最大/最小，没有乘法运算。资源余量充足。

## 4.9 时序收敛

| 阶段 | WNS |
|---|---:|
| HLS 综合估算 | +0.032 ns |
| Vivado 综合 | +1.189 ns |
| **Vivado 实现（v3）** | **+0.544 ns**（WHS +0.026 ns，`Timing MET`） |

## 4.10 多次测量的一致性

| 测量轮次 | 核心（软 / 硬） | 加速比 | 单帧延迟 median |
|---|---|---|---|
| 独立基准 | 168.35 / 4.476 ms | 37.6× | 9.426 ms（2000 帧） |

## 4.11 真实拍摄链路的实测

手机拍摄打印的眼底图 → 板端自动定位眼底圆 → FPGA 加速分割 → 大屏显示，全流程已打通。
两轮实测：端到端 **2.30×**，核心 **4.476 ms / 37.9× / 223 fps**，硬软输出 **0 像素不一致**，
与标准数据集口径一致。
